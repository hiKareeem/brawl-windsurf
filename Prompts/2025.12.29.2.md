## PROMPT 3 / Workstream: Scouting lifecycle — auto-clear / repair scouted state when target becomes invalid

ROLE: Senior Unreal C++ engineer. You own hardening the **lifecycle** of scouting state over time.

CONTEXT:
- `ServerRequestScoutPlayer` rejects scouting spectators and eliminated players.
- The viewer’s `ScoutedBoardActor` auto-follows the target’s `ActiveBoardActor`.
- We need to ensure scouting state does not get “stuck” pointing at invalid targets.

SCOPE (DO):
- Implement server-authored maintenance so that if a player becomes an invalid scout target, any viewers currently scouting them are repaired:
  - When a player becomes a spectator OR their `Life` transitions to `<= 0`, clear viewers’ scouted state (`ScoutedPlayerId = INDEX_NONE`, `ScoutedBoardActor = nullptr`).
- Add automation coverage in LVL_Sandbox validating this behavior (server-side).

SCOPE (DO NOT):
- Do not change replication shape.
- Do not add new GameplayTags or Attributes.
- Do not add EventLog event types unless you STOP and ask.

IMPLEMENTATION NOTES:
- Prefer implementing the “repair viewers scouting me” loop close to where the invalidation occurs (e.g., `SetIsSpectator`, or the server-side life application path).
- Keep the loop deterministic by iterating `GameState->PlayerArray` and using stable `PlayerId` comparisons.

DELIVERABLES:
- Code change in `Source/BrawlMatch/Public+Private/Game/BrawlPlayerState.*` (or the closest authoritative place).
- New/updated test under `Source/BrawlMatch/Private/Tests/`.

ACCEPTANCE CRITERIA:
- Viewers do not remain stuck scouting an invalid target.
- No new assets.
