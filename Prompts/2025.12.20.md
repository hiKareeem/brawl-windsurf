# Workstream A — Projectile Event Contract: Spawn→Impact Pairing, Timebase, and Ordering

## Objective
Make `ABrawlProjectileActor` comply with the event-log contract:
- Every emitted `Combat.ProjectileSpawned` must have **exactly one** terminal `Combat.ProjectileImpacted` for the same `ProjectileId`.
- `Combat.ProjectileImpacted` must be emitted **before** any `Combat.DamageApplied` that the impact causes.
- All timestamp fields (`ServerTimeSeconds`, `SpawnTimeSeconds`, `ImpactTimeSeconds`) must use the **same timebase** (match-context time when available).

## Constraints
- Server-only emission (clients never author events).
- Do not introduce new module dependencies (keep changes in **BrawlAbilities**).
- Preserve the existing projectile replication fields (do not change what replicates; only fix event behavior).

## Files
- Update:
  - `Source/BrawlAbilities/Public/Actors/BrawlProjectileActor.h`
  - `Source/BrawlAbilities/Private/Actors/BrawlProjectileActor.cpp`

## Tasks
1) **Ensure terminal `Combat.ProjectileImpacted` emission on all destroy paths**
   - Add a server-only cleanup hook (`EndPlay` or `Destroyed`) that publishes a terminal `Combat.ProjectileImpacted` when the projectile is destroyed without an impact.
   - Represent miss/expiry by leaving `ImpactedTargetId` invalid but still providing:
     - `bHasImpactPosition = true`
     - `ImpactPosition = GetActorLocation()` (best-known final position)
   - Guarantee: exactly one terminal impact event per projectile instance (avoid double-emits if both `HandleImpact` and `EndPlay` fire).

2) **Fix ordering: Impacted before DamageApplied**
   - In `HandleImpact(...)`, publish `Combat.ProjectileImpacted` **before** applying `ImpactSpecHandle` to the target ASC.
   - (This ensures `Combat.ProjectileImpacted` appears in the buffer before `Combat.DamageApplied` for that same impact.)

3) **Fix intended vs actual target fields**
   - `FBrawlEventBase::TargetUnitId` on both spawn and impact should represent the **intended** target at spawn time (`TargetUnitId`).
   - `FBrawlCombatProjectileImpactedEvent::ImpactedTargetId` represents the **actual** impacted unit (may be invalid for miss/expiry).

4) **Unify timebase for extra timestamps**
   - Set `SpawnTimeSeconds` and `ImpactTimeSeconds` using the same timebase as `ServerTimeSeconds`:
     - `Now = MatchContext ? MatchContext->GetServerTimeSeconds() : World->GetTimeSeconds()`
   - Use `Now` for:
     - `SpawnTimeSeconds` (and any internal `SpawnTimeSeconds` field stored on the actor)
     - `ImpactTimeSeconds`
   - Avoid mixing match time and `UWorld::GetTimeSeconds()` within the same event payload.

## Acceptance Criteria
- In event log buffer, for each projectile ID:
  - Exactly one `Combat.ProjectileSpawned` and exactly one `Combat.ProjectileImpacted` exist.
  - The impacted event is emitted even on miss/expiry/destroy.
- When an impact applies damage:
  - The buffered ordering is `Combat.ProjectileImpacted` **before** `Combat.DamageApplied`.
- `SpawnTimeSeconds` / `ImpactTimeSeconds` use the same timebase as `ServerTimeSeconds`.

## Rules Applied
- brawl-event-log-schema.md (projectile pairing + impact ordering + timebase)
- brawl-implementation.md (server authority)
- brawl-replication-contract.md (event emission is server-owned; avoid dependency violations)

# Workstream B — Unit Death v1: State.Dead Tag + Combat.UnitDied Event

## Objective
Add minimal server-authoritative “death” handling so that when a unit’s health reaches 0:
- the unit is marked dead via `State.Dead`
- a `Combat.UnitDied` event is published (exactly once)

## Constraints
- Server-only: death state and events are authored only on the server.
- No new module dependency violations (keep implementation in existing modules).
- Emit death only when transitioning from alive → dead (do not spam on repeated damage while already dead).

## Files
- Update:
  - `Source/BrawlAbilities/Private/GAS/Attributes/BrawlAttrSet_Combat.cpp`

## Tasks
1) **Detect lethal damage and set `State.Dead`**
   - In `UBrawlAttrSet_Combat::PostGameplayEffectExecute`, after applying damage to `CurrentHealth`:
     - If `CurrentHealth <= 0` AND the owning ASC does not already have `BrawlGameplayTags::State::Dead`, add `State.Dead`.
   - Ensure this runs only on the server (`World->GetNetMode() != NM_Client`).

2) **Publish `Combat.UnitDied`**
   - Publish `FBrawlCombatUnitDiedEvent` via `UBrawlEventBusSubsystem`.
   - Required fields:
     - `EventType = "Combat.UnitDied"`
     - `UnitId` = dead unit’s `FBrawlUnitInstanceId`
     - `KillerId` = instigator unit id when available (from effect context original instigator ASC)
     - `TimeSeconds` must use the same timebase as `ServerTimeSeconds` (match context when available)
   - Set base IDs consistently:
     - `InstigatorUnitId` = killer id (if known)
     - `TargetUnitId` = dead unit id

3) **Ordering**
   - When the death was caused by an impact that also logs damage:
     - `Combat.DamageApplied` must be published before `Combat.UnitDied` (OnDamaged → OnDeath ordering).

## Acceptance Criteria
- After lethal damage:
  - `State.Dead` is present on the target’s ASC.
  - `ABrawlUnitCharacter::IsAlive()` returns false.
  - Exactly one `Combat.UnitDied` event is emitted for that unit.
- `Combat.UnitDied` occurs after the corresponding `Combat.DamageApplied` in buffered order.

## Rules Applied
- brawl-gameplay-tags-contract.md (State.Dead ownership)
- brawl-event-log-schema.md (Combat.UnitDied requirements + ordering)
- brawl-implementation.md (server authority)

# Workstream C — Automation Tests: Projectile Contract + Unit Death

## Objective
Add dedicated-server-safe automation tests that validate Workstreams **A** and **B** using the EventBus + MatchEventLog buffer.

## Constraints
- Dedicated-server compatible (no `UGameplayStatics::CreatePlayer`).
- Use the existing pattern of opening `/Game/Brawl/Maps/LVL_Sandbox`.
- Decode buffered event payloads via `UScriptStruct::InitializeStruct` + `CopyScriptStruct` (no `reinterpret_cast`).
  - Always validate `Entry.EventStruct == TEvent::StaticStruct()` before decoding (do not rely on size-only checks).

## Files
- Update:
  - `Source/BrawlMatch/Private/Tests/BrawlEventLog_BufferingAutomationTest.cpp` (replace `reinterpret_cast` helper with type-safe struct copy-out)
- Add (either as separate tests or a single combined file):
  - `Source/BrawlMatch/Private/Tests/BrawlCombat_ProjectileEventContractAutomationTest.cpp`
  - `Source/BrawlMatch/Private/Tests/BrawlCombat_UnitDeathAutomationTest.cpp`

## Test Scenarios
### 1) Projectile Spawn→Impact Pairing (miss/expiry path)
1) `AutomationOpenMap("/Game/Brawl/Maps/LVL_Sandbox")`.
2) Get subsystems:
   - `UBrawlEventBusSubsystem`
   - `UBrawlMatchEventLogSubsystem`
3) Clear buffer.
4) Spawn an `ABrawlProjectileActor` and call `InitializeProjectile(...)` with a known `ProjectileId` (use the optional `InProjectileId` argument).
   - Use a valid `SourceUnitId` and `TargetUnitId`, but do **not** cause a real hit.
   - Immediately call `Destroy()` (or allow it to expire if you prefer), then wait a short time (latent) for `EndPlay`.
5) Assert buffered events contain (in order):
   - exactly one `FBrawlCombatProjectileSpawnedEvent` with that `ProjectileId`
   - exactly one `FBrawlCombatProjectileImpactedEvent` with that `ProjectileId`
   - impacted has `bHasImpactPosition == true`
   - impacted has invalid `ImpactedTargetId`

### 2) Impact ordering (Impacted before DamageApplied)
1) Clear buffer.
2) Spawn Source + Target `ABrawlUnitCharacter` and init both ASCs.
3) If `World->GetGameState()` is `ABrawlGameState`, set phase to `Phase.Combat` (so DamageApplied logging is enabled).
4) Build a transient damage `FGameplayEffectSpecHandle` using `UBrawlExecCalc_Damage` (pattern from `BrawlGASCombatMath_DamageAutomationTest.cpp`).
5) Spawn projectile and initialize it so it collides with the target (short distance + high speed).
6) Wait latently until both events appear in the buffered log.
7) Assert the first `Combat.ProjectileImpacted` entry’s `SequenceNumber` is **less than** the first `Combat.DamageApplied` entry’s `SequenceNumber`.

### 3) Unit death event + State.Dead
1) Clear buffer.
2) Spawn Source + Target units; init ASCs.
3) Ensure combat phase when available (same as above).
4) Apply a single damage spec large enough to kill the target.
5) Assert:
   - target ASC has `State.Dead`
   - buffer includes exactly one `Combat.DamageApplied` and exactly one `Combat.UnitDied`
   - `Combat.UnitDied.UnitId` matches the target unit id
   - `Combat.UnitDied.KillerId` matches the source unit id (when available)
   - `Combat.UnitDied` sequence number is after `Combat.DamageApplied`

## Acceptance Criteria
- Tests pass reliably and are dedicated-server safe.
- All buffered event payload decoding in tests uses reflection copy-out (no `reinterpret_cast`).
- Tests demonstrate:
  - projectile terminal event pairing
  - impacted-before-damage ordering
  - dead tagging + unit death event emission

## Rules Applied
- brawl-testing-matrix.md (automation constraints)
- brawl-event-log-schema.md (buffer decoding + projectile pairing + ordering)
- brawl-implementation.md (server authority)

# Small Prompt — Test Harness Standardization (apply before new gameplay workstreams)

## Objective
Standardize automation-test harness patterns so future tests (including Economy/Shop, StarLevel, roster) are stable and consistent.

## Requirements
1) **Sandbox world readiness gating**
   - When a test opens `/Game/Brawl/Maps/LVL_Sandbox`, prefer selecting a `Game`/`PIE` world whose `GetMapName()` contains `LVL_Sandbox`.
   - Ignore `World->bIsTearingDown` worlds.
   - In latent `Update()`, early-return `false` until:
     - `World != nullptr`
     - `World->HasBegunPlay() == true`
     - `World->GetMapName().Contains("LVL_Sandbox") == true`
   - Always reject `World->GetNetMode() == NM_Client`.

2) **Typed EventLog payload decoding (no reinterpret_cast)**
   - When validating buffered events, decode `FBrawlMatchBufferedEventEntry::EventBytes` via reflection copy-out:
     - validate `Entry.EventStruct == TEvent::StaticStruct()`
     - `StaticStruct()->InitializeStruct(&OutValue)`
     - `StaticStruct()->CopyScriptStruct(&OutValue, Entry.EventBytes.GetData())`
     - `StaticStruct()->DestroyStruct(&OutValue)`
   - Prefer the local `TScopedCopiedEvent<TEvent>` + `TryCopyEventFromEntry(...)` helper pattern used by the projectile contract tests.

3) **Projectile impact ordering test mitigation**
   - When asserting `ProjectileImpacted` occurs before `DamageApplied`, do **not** match the first `DamageApplied` event globally.
   - Instead:
     - Find the first `ProjectileImpacted` for the specific `ProjectileId` under test.
     - Use that impacted payload’s `InstigatorUnitId` + `TargetUnitId` (and optionally `AbilityId`, if set) to find the corresponding `DamageApplied`.
     - Compare their `SequenceNumber` values.

## Acceptance Criteria
- All new tests follow the same world-selection + readiness-gating pattern.
- No automation tests `reinterpret_cast` buffered event bytes.
- Projectile ordering tests match the correct paired damage event (reduces flakiness when other damage occurs).
