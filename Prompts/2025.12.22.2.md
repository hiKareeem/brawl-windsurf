# Prompt 1 — Workstream C / Q3 Option B: Centralized Combat Driver (replace per-unit ticking)

## Objective
Implement a centralized server-authoritative combat update loop that preserves existing combat behavior and structured event emission, while disabling per-unit `UBrawlUnitCombatBrainComponent` ticking.

## Non-negotiable constraints
- Must preserve **server authority** and avoid trusting clients.
- Must preserve event contracts and ordering already covered by existing tests:
	- `Source/BrawlMatch/Private/Tests/BrawlCombat_ProjectileEventContractAutomationTest.cpp`
	- `Source/BrawlMatch/Private/Tests/BrawlCombat_UnitDeathAutomationTest.cpp`
- Must keep module boundaries:
	- Match-level orchestration belongs in `BrawlMatch`.
	- Unit logic stays in `BrawlUnit`.
	- Targeting/ability/events stay in `BrawlAbilities`.
- When iterating units, preserve deterministic ordering by `FBrawlUnitInstanceId` (stable ID).

- Autocast brain (current per-unit tick):
	- `Source/BrawlUnit/Public/Components/BrawlUnitCombatBrainComponent.h`
	- `Source/BrawlUnit/Private/Components/BrawlUnitCombatBrainComponent.cpp`
- Match context + phase:
	- `Source/BrawlMatch/Public/Game/BrawlGameState.h`
	- `Source/BrawlMatch/Private/Game/BrawlGameState.cpp`

	- `Source/BrawlMatch/Private/Components/BrawlRoundManagerComponent.cpp`
- Targeting + events:

	- `Source/BrawlCore/Public/Events/BrawlEvents.h`
	- `Source/BrawlCore/Public/Subsystems/BrawlEventBusSubsystem.h`

## Implementation tasks (references-only)
- Disable per-unit `UBrawlUnitCombatBrainComponent` ticking on the server and route “combat step” calls through the centralized driver.
	- The centralized driver should be phase-gated using `IBrawlMatchContextInterface::GetPhaseTag()` (or `ABrawlGameState::GetPhaseTag()`), acting only during `Phase.Combat`.
	- Preserve (or explicitly decide to remove) the existing dev override `brawl.CombatBrain.ForceTick` currently defined in `BrawlUnitCombatBrainComponent.cpp`.
- Central driver enumerates combat-capable units and calls into a deterministic “try autocast” path.
	- Enumeration source must be explicit and stable (examples: iterate `TActorIterator<ABrawlUnitCharacter>`, or maintain a registered set).
	- Sort iteration deterministically by stable `FBrawlUnitInstanceId.Value`.
- Ensure the driver does not introduce new per-frame allocations or per-unit expensive queries.
	- Prefer caching unit lists per combat start if possible.
- Preserve combat event emission behavior:
	- `Combat.TargetChosen` and `Combat.AbilityCast` should still be emitted from the existing ability/brain pathway (see `UBrawlGA_Base`).
	- Projectile + damage + death event ordering must remain compliant.

## Acceptance criteria
- No unit-level ticking is required for combat casting behavior in `Phase.Combat`.
- Existing combat automation tests remain green:
	- `Brawl.Combat.ProjectileEventContract.*.LVL_Sandbox`
	- `Brawl.Combat.UnitDeath.LVL_Sandbox`
	- `Brawl.GAS.Abilities.DataDriven.*` (see `BrawlGASAbilities_DataDrivenAutomationTest.cpp`)
- Ability cast behavior remains functionally equivalent (basic casts on cooldown; ultimate casts when energy full).
- Iteration order is deterministic and based on stable IDs.

## Suggested new/updated tests (references-only)
- Add a new latent `LVL_Sandbox` test (or extend an existing one) to assert:
	- per-unit combat brain tick is disabled, but centralized driver still produces casts/events.
	- reference pattern: `Source/BrawlMatch/Private/Tests/BrawlEquipAbilitiesAutomationTest.cpp` latent command structure.

# Prompt 2 — Workstream D / Task-4: Traits v1 Automation Tests

## Objective
Add automation tests that validate trait counting invariants and recompute triggers (Active vs Potential) with server authority.

## Primary reference locations
- Trait data + component:
	- `Source/BrawlEconomy/Public/Data/BrawlTraitData.h`
	- `Source/BrawlEconomy/Public/Components/BrawlTraitComponent.h`
- Player-owned hooks:
	- `Source/BrawlMatch/Public/Game/BrawlPlayerState.h`
	- `Source/BrawlMatch/Private/Game/BrawlPlayerState.cpp`
- Placement + bench/field derivation:
	- `Source/BrawlGrid/Public/Actors/BrawlBoardActor.h`
	- `Source/BrawlGrid/Private/Actors/BrawlBoardActor.cpp` (occupancy and coord helpers)
- Automation harness patterns:
	- `Source/BrawlMatch/Private/Tests/BrawlAutomationTestHelpers.h`
	- `Source/BrawlMatch/Private/Tests/BrawlPlacementAutomationTest.cpp`

## Required scenarios (minimum)
- Scenario A: Bench vs field counting
	- Setup a player with at least 2 owned units whose `UBrawlUnitData::BaseTags` include known `Trait.*` tags.
	- Place one unit on bench and one on field.
	- Assert:
		- Potential counts include both units.
		- Active counts include only the field unit.
- Scenario B: Recompute on roster mutation
	- Add/remove a unit from roster via server APIs.
	- Assert trait counts update.
- Scenario C: Recompute on placement commit
	- Move a unit bench <-> field via the authoritative server move pathway.
	- Assert counts update appropriately.

## Constraints
- Tests should follow the existing `LVL_Sandbox` latent pattern and require `NetMode != NM_Client`.
- Treat bench/field status as **derived** from board occupancy / grid snapshot, not from actor transform.

## Acceptance criteria
- Traits counts match the Active/Potential contract described in `Prompts/2025.12.22.md` Workstream D section.
- Trait recomputation occurs at the intended trigger points (roster changes and placement commits).
