# 2025.12.24.0 — Workstreams (Arena transfer, Replay/Event Log export, ReplicationGraph)

## Current status / handoff (as of 2025-12-24)
- **Core loop exists:** `UBrawlRoundManagerComponent` cycles phases; `UBrawlCombatManagerComponent` ticks server-only in `Phase.Combat`.
- **Sandbox arena is stubbed:** `ABrawlSandboxGameMode::TrySandboxSetupArenaForFirstTwoPlayers()` fakes an arena by assigning both PlayerStates to one board + seeding both benches (no real transfer plan + no return).
- **Match lifecycle hooks implemented:** match end is a replicated signal on `ABrawlGameState` (`bMatchEnded`); `UBrawlRoundManagerComponent` ends the match when `RoundSet` is exhausted.
- **GameMode split:** `ABrawlGameMode` is shipping-clean (lifecycle + replay/log export); `ABrawlSandboxGameMode` owns sandbox board spawning/seeding + debug Exec commands (`BrawlDebugAdvancePhase`, `BrawlDebugAdvanceRound`, `BrawlDebugEndMatch`).
- **Replay recording implemented (INI gated):** `ABrawlGameMode` starts recording on match start and stops on match end via `UBrawlReplaySubsystem` (`UGameInstance::StartRecordingReplay`/`StopRecordingReplay`).
- **Event log export implemented (INI gated):** `ABrawlGameMode` exports buffered `UBrawlMatchEventLogSubsystem` events to JSONL on match end.
- **ReplicationGraph remains pending:** `UBrawlReplicationGraph` exists, but Workstream D wiring/implementation is not done yet.

## Artifacts + config (INI-only)

# Workstream B — Arena transfer model (combat host board + return) (Milestone 7 / scale)

## Objective
Implement match-owned orchestration to transfer opponent units onto an arena host board at combat start, then return them after combat.

## Rules / constraints
- Board occupancy is canonical; transforms are derived from occupancy commits.
- Transfer uses canonical `FBrawlGridCoord` and must respect the host/guest half rotation rules.
- Must not break roster ownership (roster remains per-player; placement is per-board occupancy).

## Primary references
- Arena/transfer rules + coord mapping:
    - `rules/brawl-implementation.md` (Arena terminology, transfer mapping, bench rows)
- Board ownership + occupancy:
    - `Source/BrawlGrid/Public/Actors/BrawlBoardActor.h`
    - `Source/BrawlGrid/Private/Actors/BrawlBoardActor.cpp`
- Match phase transitions:
    - `Source/BrawlMatch/Public/Components/BrawlRoundManagerComponent.h`
    - `Source/BrawlMatch/Private/Components/BrawlRoundManagerComponent.cpp`

## Decision points
- Arena host selection:
    - one player’s home board is the arena host
- What is persisted to return units:
    - original board actor + original coord snapshot per unit (recommended)
- PlayerState board refs:
    - Keep `ABrawlPlayerState::BoardActor` as “home board” and optionally introduce an additional “current arena board”

## Tasks (references-only)
1) Add a match-owned “transfer plan” representation
    - For each unit being transferred, record:
        - unit id
        - from board + from coord
        - to board + to coord
    - Apply transfers in deterministic order (sort by `FBrawlUnitInstanceId.Value`)

2) Implement transfer at combat start
    - On entering `Phase.Combat`, move the guest player’s units (field + bench) onto the host board’s guest half / guest bench row
    - Apply 180° rotation mapping per the contract rules
    - Ensure the board’s host/guest player id assignments are correct so placement validation continues to work

3) Implement return after combat
    - On exiting combat (entering `Phase.Rewards` or next `Phase.Planning`), return transferred units to their original boards/coords
    - Ensure dead units are handled per match rules (destroyed/removed appropriately)

## Acceptance criteria
- During combat, both players’ units appear on the arena host board in the correct halves and bench rows.
- After combat, units return to their original boards/coords.
- Placement legality rules remain phase-gated and enforced server-side.

## Test expectations
- Add an automation test that:
    - seeds units on two boards
    - transitions to combat
    - asserts guest units are present on host board with expected mirrored coords
    - transitions back and asserts return mapping

# Workstream C — Replay + structured Event Log export (Milestone 6)

## Objective
Start/stop server replay recording and export a stable, schema-versioned structured event log artifact at match end.

## Rules / constraints
- Server-only authority: clients never author events or artifacts.
- Event log timebase must match `FBrawlEventBase.ServerTimeSeconds`.

## Primary references
- Event log schema + buffering:
    - `rules/brawl-event-log-schema.md`
    - `Source/BrawlMatch/Public/Subsystems/BrawlMatchEventLogSubsystem.h`
- Replay requirement:
    - `rules/brawl-replication-contract.md` (DemoNetDriver replay)
- (If/when present) replay subsystem:
    - `Source/BrawlNet/Public/Subsystems/BrawlReplaySubsystem.h`

## Dependencies
- Requires `BrawlNet` skeleton if using `UBrawlReplaySubsystem`.
- If `BrawlNet` is not available, you can still implement event log export purely in `BrawlMatch`.

## Tasks (references-only)
1) Use Workstream A’s authoritative match start/end hooks (don’t define separate ones here)

2) Implement replay recording hooks
    - Start recording on match start; stop on match end
    - Attach metadata: MatchId, map name, build/version

3) Implement event log export
    - Export buffered events from `UBrawlMatchEventLogSubsystem` to a stable file format (JSONL is a common choice)
    - Include required base fields + payload type identity
    - Schema versioned
    - Apply ordering/stability rules per `rules/brawl-event-log-schema.md` (persistence layer responsibility)

## Acceptance criteria
- Match end produces:
    - a replay artifact (when enabled)
    - a structured event log artifact with schema version
- Exported events use the correct timebase and stable IDs.

# Workstream D — ReplicationGraph relevancy (Milestone 6+)

## Objective
Scale replication for 8 boards / 4 arenas + spectator by implementing ReplicationGraph relevancy rules.

## Rules / constraints
- Do not “replicate everything to everyone”.
- Relevancy must support:
    - player sees own board + current opponent arena
    - spectator can opt into all boards

## Primary references
- Replication contract:
    - `rules/brawl-replication-contract.md` (ReplicationGraph required)
- (If/when present) replication graph class:
    - `Source/BrawlNet/Public/Net/BrawlReplicationGraph.h`

## Dependencies
- Requires `BrawlNet` skeleton.

## Tasks (references-only)
1) Wire ReplicationGraph enablement (config + runtime)
    - Decide how `UBrawlNetSettings::bEnableReplicationGraph` is applied (INI-only vs runtime switching)
    - Ensure the correct ReplicationDriver class is actually used by the NetDriver
2) Implement `UBrawlReplicationGraph : UReplicationGraph`
3) Define routing groups for:
    - each board’s actors (board + units + projectiles)
    - match-global actors (GameState)
4) Implement per-connection relevancy assignment
    - players assigned to relevant boards
    - spectator override

## Acceptance criteria
- In an 8-board scenario, clients receive only relevant board actors by default.
- Spectator can view all boards when enabled.
