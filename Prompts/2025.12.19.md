# Workstream D — Combat Loop v1: Data-driven Ability Execution (Cooldown + Energy + Damage)

## Objective
Implement a minimal end-to-end server-authoritative ability execution pipeline driven by `UBrawlAbilityData`, so in `Phase.Combat`:
- **Basics** auto-cast when off cooldown.
- **Ultimates** auto-cast when `CurrentEnergy >= MaxEnergy` (default policy).

A successful cast must:
- publish `Combat.TargetChosen` + `Combat.AbilityCast` using match-context timebase
- apply cooldown scaled by Spd via `UBrawlMMC_CooldownDuration` using `Data.CooldownBaseSeconds`
- apply damage via `UBrawlExecCalc_Damage` using `Data.Power` (+ optional `Data.Mod` / `Data.Flat`) and asset tags `DamageClass.*` / `Element.*`
- apply energy spend/gain deterministically on the server (`Data.EnergyCost`, `Data.EnergyGained`)

## Constraints
- Dedicated-server authoritative only; clients never author outcomes.
- Do **not** add `Phase.ItemShop` to the round flow (RoundManager stays Planning → Combat → Rewards for now).
- Preserve module boundaries:
  - **BrawlAbilities** may depend only on BrawlCore + UE/GAS; it must NOT include BrawlUnit/BrawlMatch/BrawlAI headers.
  - **BrawlUnit** may call into BrawlAbilities (ASC, ability classes), but must not introduce Match-flow ownership (Phase remains owned by Match/GameState).
- Tests must be dedicated-server safe (no `UGameplayStatics::CreatePlayer`).

## Relevant Existing Code (do not duplicate)
- `UBrawlUnitLoadoutComponent::Equip(...)` grants abilities using `UBrawlAbilityData::AbilityClass` and sets `FGameplayAbilitySpec::SourceObject` to the `UBrawlAbilityData` instance.
- `UBrawlUnitCombatBrainComponent` already:
  - runs server-only in `Phase.Combat`
  - calls `CanActivateAbility` then `TryActivateAbility`
- Central policies already exist:
  - `UBrawlExecCalc_Damage` (uses `Data.Power`, `Data.Mod`, `Data.Flat` and asset tags)
  - `UBrawlMMC_CooldownDuration` (uses `Data.CooldownBaseSeconds` and captures Speed)

## Tasks
1) **Add a minimal concrete data-driven GameplayAbility in BrawlAbilities**
   - Create `UBrawlGA_DataDrivenBasic` (and optionally `UBrawlGA_DataDrivenUltimate`) derived from `UBrawlGA_BasicBase` / `UBrawlGA_UltimateBase`.
   - On the server in `ActivateAbility`:
     - Resolve `const UBrawlAbilityData* AbilityData` from `GetCurrentSourceObject()` (or the spec source object).
     - Load `TargetingPolicy` from `AbilityData->TargetingPolicy` and resolve a `FBrawlTargetResult` against the avatar actor.
     - If no target, end ability without committing cost/cooldown.
     - Publish `Combat.TargetChosen` and `Combat.AbilityCast` using the `UBrawlGA_Base` helpers (match-context timebase).
     - Build and apply damage:
       - Create an outgoing damage spec that uses `UBrawlExecCalc_Damage`.
       - Set `Data.Power = AbilityData->BasePower`.
       - Optionally set `Data.Mod = 1.0` and `Data.Flat = 0.0` (or allow future extension).
       - Append asset tags: `AbilityData->DamageClassTag` and `AbilityData->ElementTag`.
       - If `AbilityData->ProjectilePolicy` is set, spawn `ABrawlProjectileActor` using policy values and pass the spec for impact application; otherwise apply the damage spec instantly to the target ASC.
     - Apply energy to the caster ASC:
       - Subtract `AbilityData->EnergyCost` from `CurrentEnergy` (clamped 0..MaxEnergy).
       - Add `AbilityData->EnergyGained` to `CurrentEnergy` (clamped).
     - Apply cooldown to the caster ASC:
       - Apply a duration GE whose duration magnitude uses `UBrawlMMC_CooldownDuration` and set `Data.CooldownBaseSeconds = AbilityData->CooldownBaseSeconds`.

2) **Update ultimate gating to “energy full”**
   - In `UBrawlUnitCombatBrainComponent::TryAutocastAbility`, when attempting the ultimate:
     - Require `CurrentEnergy + KINDA_SMALL_NUMBER >= MaxEnergy` (default TFT-like rule).
     - Keep `CanActivateAbility` as the authoritative cooldown/CC gate.

3) **Add/extend automation tests**
   - Add one latent test that:
     - opens `/Game/Brawl/Maps/LVL_Sandbox`
     - spawns two `ABrawlUnitCharacter`s and equips a test ability (using the normal loadout path)
     - activates the basic and asserts:
       - target health decreases (damage path works)
       - caster energy updates as expected
       - a cooldown effect is applied with duration equal to `UBrawlMMC_CooldownDuration` for known Speed/BaseCooldown
   - Add a second test (or extend the first) asserting ultimates do not fire until energy is full.

## Acceptance Criteria
- In `Phase.Combat`, units can successfully auto-cast basic and ultimate abilities server-side.
- Damage numbers are produced by `UBrawlExecCalc_Damage` and remain consistent with existing combat-math tests.
- Cooldown duration scales via `UBrawlMMC_CooldownDuration` using `Data.CooldownBaseSeconds`.
- Ultimate gating uses `CurrentEnergy >= MaxEnergy` (not “>= cost”) as the default rule.
- No new cross-module dependency violations.
- Automation tests are dedicated-server safe.

# Workstream E — Unit Attribute Initialization v1 (UnitData-driven stat curves + server-side initialization + automation test)

## Objective
Initialize a unit’s starting attributes on the **server** based on `UBrawlUnitData` (including per-star scaling), so:
- Combat math uses real stats (Atk/Def/Spd/etc.) without test-only `SetNumericAttributeBase` calls.
- Pooled attributes start in a consistent state (health full, energy empty by default).

## Constraints
- Server-only: base attribute initialization is authored on the server.
- Preserve module boundaries:
  - Implementation lives in **BrawlUnit**.
  - **BrawlAbilities** must not depend on **BrawlUnit**.
- Data-driven: stats come from `UBrawlUnitData` curve/table references (no hard-coded per-unit numbers in C++).

## Files
- Update:
  - `Source/BrawlUnit/Public/Data/BrawlUnitData.h`
  - `Source/BrawlUnit/Private/Data/BrawlUnitData.cpp`
  - `Source/BrawlUnit/Private/Actors/BrawlUnitCharacter.cpp`
- Add (recommended; aligns with directory map):
  - `Source/BrawlUnit/Public/Components/BrawlUnitDefinitionComponent.h`
  - `Source/BrawlUnit/Private/Components/BrawlUnitDefinitionComponent.cpp`

## Tasks
1) **Extend `UBrawlUnitData`**
   - UBrawlUnitData has a single UCurveTable soft ptr where each row is a stat (MaxHealth, Attack, SpecialAttack, Defense, SpecialDefense, Speed, MaxEnergy), and the curve is evaluated at X = StarLevel (1–3)
   - Provide enough authorable data to resolve per-star values for:
     - `MaxHealth`, `Attack`, `SpecialAttack`, `Defense`, `SpecialDefense`, `Speed`, `MaxEnergy` (all *may* have global defaults 100/50/50/50/50/100/100 unless overridden, but leaving them 0/null is also valid)
   - Star level input is `ABrawlUnitCharacter::StarLevel`.

2) **Apply base attributes when UnitData is known (server-side)**
   - Centralize this in a unit-definition/init path (preferred: `UBrawlUnitDefinitionComponent`).
   - After `ASC->InitAbilityActorInfo(...)`, set base values on the owning ASC:
     - `MaxHealth` and `CurrentHealth` (spawn full HP)
     - `MaxEnergy` and `CurrentEnergy` (spawn at 0 energy unless otherwise specified)
     - `Attack`, `SpecialAttack`, `Defense`, `SpecialDefense`, `Speed`
   - Ensure idempotency (safe to call multiple times) and deterministic evaluation.

3) **Add a dedicated-server automation test for attribute init**
   - Spawn a unit with a transient `UBrawlUnitData` containing known curve table values.
   - Run the init path and assert the ASC numeric attributes match expected results.

## Acceptance Criteria
- A spawned unit with `UnitData` has non-zero combat stats without per-test manual attribute setup.
- Spawn pooled state is correct:
  - `CurrentHealth == MaxHealth`
  - `CurrentEnergy == 0` (default)
- Initialization is server authoritative and deterministic.
