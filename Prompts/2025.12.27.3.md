## Workstream 1 — Net/Match: implement the decided replication visibility policy

### Objective
Make the networked game match the visibility contract:
- All players can see all players’:
  - player name
  - roster
  - bench (bench vs field status as exposed by canonical board occupancy)
  - life
  - gold
  - streak
  - XP / level
- Spectators can additionally see:
  - all shop offers
  - all board grid occupancy

### Constraints / invariants
- Keep bandwidth controlled via ReplicationGraph (do not blindly replicate everything to everyone).
- Preserve server authority: no client-authored visibility or “request-based reveal”.

### Primary references
- `rules/brawl-replication-contract.md`
- `Source/BrawlMatch/Public/Game/BrawlPlayerState.h` (currently many fields are `COND_OwnerOnly`)
- `Source/BrawlEconomy/Public/Components/BrawlEconomyComponent.h`
- `Source/BrawlEconomy/Public/Components/BrawlProgressionComponent.h`
- `Source/BrawlEconomy/Public/Components/BrawlShopComponent.h`
- `Source/BrawlGrid/Public/Actors/BrawlBoardActor.h` (Occupancy FastArray)
- `Source/BrawlNet/Public/Net/BrawlReplicationGraph.h`

### Deliverables
- Code changes implementing the new replication conditions.
- Any necessary RepGraph routing adjustments.
- Automation coverage proving spectators can observe:
  - other players’ shop offers
  - board occupancy for a non-active board

### Acceptance criteria
- A spectator can observe:
  - all boards’ occupancy updates
  - all players’ shop offers
- A normal player can observe all players’ scoreboard data (life/gold/xp/streak/roster).

### Rules Applied
- `rules/brawl-replication-contract.md` (spectator routing + visibility)
- `rules/brawl-implementation.md` (server authority)
