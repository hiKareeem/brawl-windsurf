## Workstream 1 — Economy/Match: Allow shop purchases during `Phase.Combat` (arena-aware)

### Objective
- **Combat-phase purchasing**: Allow `ABrawlPlayerController::ServerRequestShopPurchaseOffer(...)` during `Phase.Combat`.
- **Arena correctness**: If the purchaser is the **guest** (their `ActiveBoardActor` is an arena board), newly purchased units must round-trip back to their home board when combat ends.

### Constraints / invariants
- **Server authority**: Client sends requests only; server validates phase, affordability, bench space, and legality.
- **Occupancy is canonical**: Board occupancy drives placement; transforms are derived.
- **Roster ownership invariant**: Purchased units belong to the purchasing `ABrawlPlayerState` roster regardless of which board they are on.
- **Bench-only in combat**: Purchases during `Phase.Combat` must spawn on the purchaser’s allowed bench row on the *active* board.

### Primary references
- **RPC**: `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp` (`ServerRequestShopPurchaseOffer_Implementation`)
- **Board selection**: `ABrawlPlayerState::GetActiveBoardActor()` / `GetBoardActor()`
- **Bench legality**: `ABrawlBoardActor::GetHostPlayerId()` / `GetGuestPlayerId()` and bench-row checks
- **Arena return**: `ABrawlGameState::ReturnUnitsFromArenaTransferPlan()` + `FBrawlArenaTransferPlan`
- **Tests**: `Source/BrawlMatch/Private/Tests/BrawlArenaTransfer_RoundTripAutomationTest.cpp`, `.../BrawlShopPurchaseAutomationTest.cpp`

### Deliverables
- **Phase gate update**: Permit `Phase.Combat` (keep `Phase.Rewards` forbidden).
- **Active-board placement**:
  - **Use** `ActiveBoardActor` (fallback to `BoardActor`) for bench-space checks and placement.
  - **Derive** allowed bench row from `HostPlayerId/GuestPlayerId` (never trust client).
- **Arena-aware return hook**:
  - When `Phase.Combat` AND `ActiveBoardActor != BoardActor` (guest is fighting on an arena):
    - After successful spawn+place on the arena bench, append a `FBrawlArenaTransferUnitMove` to `ABrawlGameState::GetMutableArenaTransferPlan().Moves` so `ReturnUnitsFromArenaTransferPlan()` returns it.
    - Populate `FromBoard = BoardActor` (home) and `ToBoard = ActiveBoardActor` (arena). Mark `FromCoord.bIsBench = true` so return prefers bench mapping (X can be placeholder; return uses the unit’s current arena bench coord if it stayed on bench).
- **Automation test**:
  - Guest enters combat (arena transfer happens).
  - Guest purchases during `Phase.Combat`.
  - Assert unit appears on arena guest bench row.
  - Exit combat.
  - Assert unit is on guest home bench row `Y=0` at mirrored X, and not left behind on arena.

### Acceptance criteria
- **Correctness**: Guest combat purchases always return to home board after combat.
- **Security**: No client-authored outcomes; invalid phases/bench-full/insufficient-gold reject cleanly.
- **Coverage**: New test is deterministic and stable.

### Rules Applied
- `rules/brawl-implementation.md` (phase semantics; arena transfer return semantics)
- `rules/brawl-replication-contract.md` (occupancy canonical; server authority)
- `rules/brawl-server-validation-checklist.md` (request validation)

## Workstream 2 — Match: Combat end conditions v1 (multi-arena safe) + Rewards gating

### Objective
- **Per-arena resolution**: Detect when an arena fight is decided (one side has 0 alive **field** units).
- **Tie-break**: If both sides reach 0 alive field units, decide winner by the earlier `Combat.DamageApplied` ordering for the final elimination (fallback: host wins).
- **No premature global advance**: Do not advance out of `Phase.Combat` until **all** arena fights are resolved.
- **Rewards semantics**: Ensure Rewards remains locked down (no placement, no shop/economy actions).

### Constraints / invariants
- **Bench excluded**: Bench units never count toward “alive units remaining”.
- **Determinism**: Any iteration over units must be stable (`FBrawlUnitInstanceId.Value` sort).
- **No double-advance**: Early-out must not race with the existing phase timer.

### Primary references
- **Phase flow**: `Source/BrawlMatch/Private/Components/BrawlRoundManagerComponent.cpp`
- **Combat driver**: `Source/BrawlMatch/Private/Components/BrawlCombatManagerComponent.cpp`
- **Event ordering**: `Source/BrawlMatch/Public/Subsystems/BrawlMatchEventLogSubsystem.h` (`SequenceNumber`)
- **RPC phase gates**: `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp`

### Deliverables
- **Arena outcome evaluation (server-only)**:
  - Compute alive **field** counts per team for each active arena board.
  - When an arena resolves, persist enough info for Rewards (winner/loser/tie-break policy) and publish an event (e.g., `Combat.ArenaResolved`) that references the deciding `Combat.DamageApplied` SequenceNumber(s) when tie-break is used.
- **Tie-break policy**:
  - If both teams hit 0 alive field units, compare the ordering of the final-elimination damage events and award the win to the team eliminated second.
  - If ordering cannot be determined from events, default winner = host.
- **Phase advance policy**:
  - Mark arena as resolved; only trigger the existing combat->rewards transition once *all* arenas are resolved (1v1 still works).
- **Rewards gating audit**:
  - Ensure placement and all shop/economy RPCs reject while `PhaseTag == Phase.Rewards`.
- **Automation tests (LVL_Sandbox)**:
  - `EarlyOut_OneSideEmpty`: start combat with one side having 0 field units; assert arena resolves without waiting full combat duration and return plan executes.
  - `EarlyOut_DoubleElim_TieBreakFallbackHost`: contrive both sides reaching 0 and assert host wins when tie-break cannot be resolved (or tie-break chooses expected winner when it can).

### Rules Applied
- `rules/brawl-implementation.md` (combat/rewards phase semantics; do not advance while other arenas ongoing)
- `rules/brawl-event-log-schema.md` (combat event ordering/traceability)
- `rules/brawl-gameplay-tags-contract.md` (avoid new hard-meaning tags unless necessary)
