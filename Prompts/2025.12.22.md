# Workstream A — StarLevel Combine Guard: Block Field Upgrades During Phase.Combat

## Objective
Enforce the v1 rule in [rules/brawl-implementation.md](cci:7://file:///C:/Users/hi/.codeium/.windsurf/rules/brawl-implementation.md:0:0-0:0):

- Unit **StarLevel upgrades** (combines) must never resolve for a unit **actively in combat**:
    - `PhaseTag == Phase.Combat`
    - unit is **on the field** (not on the bench)
- Units **on the bench** can still combine at any point (including `Phase.Combat`).
 
This workstream is **only** the minimum “bench vs field” signal + accessors needed to enforce this rule.
The actual combine guard/deferral lives in the **combine-resolution code path** (see Workstream C), not inside `ABrawlUnitCharacter::SetStarLevel(...)`.

## Constraints
- Server authoritative only (clients never author StarLevel changes).
- Do not introduce module dependency violations:
    - [BrawlUnit](cci:2://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlUnit/BrawlUnit.Build.cs:2:0-31:1) must not depend on [BrawlMatch](cci:2://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlMatch/BrawlMatch.Build.cs:2:0-33:1) or `BrawlGrid`.
    - Use `IBrawlGridOccupantInterface` and `IBrawlMatchContextInterface` (both in **BrawlCore**) to avoid cross-module coupling.
- Only guard **upgrades** (`NewStarLevel > CurrentStarLevel`). Don’t overreach into other behaviors unless required.

## Tasks
1) **Expose authoritative “is on bench?” state to the unit (without BrawlUnit depending on BrawlGrid)**
    - Make [ABrawlUnitCharacter](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlUnit/Private/Actors/BrawlUnitCharacter.cpp:16:0-58:1) implement `IBrawlGridOccupantInterface`.
    - Store:
        - `bHasGridCoordSnapshot`
        - `FBrawlGridCoordSnapshot GridCoordSnapshot`
    - Implement:
        - `TryGetGridCoordSnapshot`
        - `SetGridCoordSnapshot`
        - `ClearGridCoordSnapshot`

2) **Have the board update the unit’s grid snapshot whenever it places/teleports it**
    - In [ABrawlBoardActor::TeleportUnitActorToCoord(...)](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlGrid/Public/Actors/BrawlBoardActor.h:128:1-128:90):
        - If the actor implements `IBrawlGridOccupantInterface`, call `SetGridCoordSnapshot` using the canonical `FBrawlGridCoord` that the board is teleporting to.

    - `SetStarLevel(...)` remains a low-level server-only setter used by init/tests.

    - A unit **on the bench** *can* upgrade during combat via the same API as long as the combine does not involve an in-combat unit.
- In `Phase.Planning` (and other non-combat phases):
    - Upgrades requested through `RequestStarLevelUpgrade(...)` apply immediately regardless of bench/field placement.
- No module dependency violations are introduced.

# Workstream C — Pending Combines v1: Defer Combat-Field Upgrades to Next Phase.Planning

## Objective
Implement the second half of the v1 rule:
- If a StarLevel upgrade is requested during `Phase.Combat` while the unit is on the **field**, it becomes a **pending combine**.
- Pending combines resolve at the start of the next `Phase.Planning` (TFT-like).

## Constraints
- Server-only. Clients never schedule or resolve combines.
- Deterministic resolution order (sort by stable `FBrawlUnitInstanceId`).
- Keep module boundaries:
    - Combine logic can live in **BrawlUnit** (component), but phase hooks should be invoked from **BrawlMatch** (since Match owns phase flow).

## Files
- Add:
    - `Source/BrawlUnit/Public/Components/BrawlStarCombineComponent.h`
    - `Source/BrawlUnit/Private/Components/BrawlStarCombineComponent.cpp`
- Update (integration point options; pick one and keep it simple):
    - Option A (explicit call site): [Source/BrawlMatch/Private/Components/BrawlRoundManagerComponent.cpp](cci:7://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlMatch/Private/Components/BrawlRoundManagerComponent.cpp:0:0-0:0)
    - Option B (GameState helper): `Source/BrawlMatch/Private/Game/BrawlGameState.cpp` (if you prefer resolving “on phase set”)

## Tasks
1) **Create `UBrawlStarCombineComponent` (server-only behavior)**
    - Stores pending entries:
        - `FBrawlUnitInstanceId UnitId`
        - `int32 DesiredStarLevel`
    - API:
        - `RequestStarLevelUpgrade(FBrawlUnitInstanceId UnitId, int32 DesiredStarLevel)`
            - Finds the unit actor (either via a provided lookup, or by scanning world actors for matching `UnitId`).
            - If `Phase.Combat` AND unit is on the field (or placement unknown), enqueue/update the pending entry.
            - Otherwise, apply immediately via [Unit->SetStarLevel(DesiredStarLevel)](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlUnit/Public/Actors/BrawlUnitCharacter.h:50:1-50:38).

2) **Resolve pending combines when planning starts**
    - On transition into `Phase.Planning`, call `ResolvePendingUpgrades()`:
        - Sort pending entries by `UnitId` (determinism).
        - For each entry:
            - If unit actor still exists and `Unit->GetStarLevel() < DesiredStarLevel`, call [SetStarLevel(DesiredStarLevel)](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlUnit/Public/Actors/BrawlUnitCharacter.h:50:1-50:38).
        - Clear resolved entries.

3) **Integration hook**
    - In [UBrawlRoundManagerComponent::StartPhase(Phase.Planning, ...)](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlMatch/Public/Components/BrawlRoundManagerComponent.h:28:4-28:70), after [GameState->SetPhaseTag(...)](cci:1://file:///E:/Unreal/BrawlFinal/Brawl/Source/BrawlMatch/Public/Game/BrawlGameState.h:31:4-31:46), invoke the combine component resolve function (wherever the component lives).
    - Keep this explicit and server-only; avoid polling/ticking.

## Acceptance Criteria
- A combat-field upgrade request is deferred and then resolves at the next planning start.
- Bench upgrades in combat phase resolve immediately (never queued) unless they involve an in-combat unit.
- Resolution order is deterministic and stable (by `UnitId`).

## Rules Applied
- brawl-implementation.md (pending combines resolve next planning; server authority)
- brawl-directories.md (module boundaries)
- brawl-replication-contract.md (server-owned state changes; replay-friendly behavior via replicated StarLevel)
