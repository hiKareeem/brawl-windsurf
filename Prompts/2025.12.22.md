# Workstream A — Shop Purchase Robustness (OfferId) + Pool Exhaustion Policy

## Objective
Harden the shop purchase path so that client requests are robust to list mutation and the shop offer rolling is well-defined when a cost bucket is exhausted.

## Constraints
- Server-authoritative commit; clients only send requests.
- Server must validate that the requested `OfferId` exists in the player’s current offer list.
- Must keep shared-pool semantics correct: reserved offers return on reroll, purchased offers stay consumed.

## Files
- Update:
	- `Source/BrawlMatch/Public/Game/BrawlPlayerController.h`
	- `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp`
	- `Source/BrawlEconomy/Public/Components/BrawlShopComponent.h`
	- `Source/BrawlEconomy/Private/Components/BrawlShopComponent.cpp`

## Tasks
1) **OfferId-based purchase request**
	- Ensure purchase RPC takes `FName OfferId`.
	- Ensure server validates offer existence via `TryGetOfferById` and consumes via `ServerConsumeOfferById`.

2) **Pool exhaustion policy is explicit**
	- Ensure `RollOffersInternal` tries multiple costs (non-repeating) before falling back to `TryTakeRandomUnitAnyCost`.
	- Keep behavior deterministic under the same seed.

3) **Verify event logging fields**
	- `Economy.Purchase` includes `OfferId`, `UnitTypeId`, `Cost`.
	- `Economy.Reroll` includes resulting `OfferIds`.

## Acceptance Criteria
- Buying an offer via `OfferId` always buys the intended offer entry (even if other offers have been removed).
- Rolling offers never immediately falls back to `AnyCost` just because the first cost bucket was empty.
- Purchase continues to keep the shared pool consumed correctly for bought offers.

# Workstream C — Combat Loop v1 Completion (AI Casts + Event Ordering)

## Objective
Get a 1v1 sandbox loop where units:
- acquire targets deterministically,
- cast basics on cooldown,
- cast ultimates when energy is full,
- apply projectile travel-time damage,
- emit required combat events in correct order.

## Constraints
- Maintain the contract ordering: **OnHit → OnDamaged → OnDeath**.
- Emit structured combat events (`Combat.TargetChosen`, `Combat.AbilityCast`, `Combat.ProjectileSpawned/Impacted`, `Combat.DamageApplied`, `Combat.UnitDied`).
- Avoid per-unit tick if possible; keep updates centralized.

## Suggested Split (parallelizable)
- **C1 (BrawlAbilities):** ensure GA bases + targeting policy + projectile events cover the event schema.
- **C2 (BrawlAI/BrawlUnit):** basic combat brain: acquire target + trigger GA when ready.
- **C3 (BrawlMatch):** phase manager combat start locks placement and starts combat timer.

See `Prompts/2025.12.22.1.md` for a codebase-grounded C1–C3 breakdown with file paths and existing tests.
