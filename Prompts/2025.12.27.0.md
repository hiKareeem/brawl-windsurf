## Workstream 1 — Match/Grid: Add automation coverage for `ServerRequestMoveUnit` phase gates + combat bench-row enforcement + Grid move events

### Objective
- Add missing **server-RPC-level** automation coverage for `ABrawlPlayerController::ServerRequestMoveUnit(UnitId, ToCoord)`.
- Verify:
  - `Phase.Rewards` rejects all move requests.
  - `Phase.Combat` allows **bench-to-bench only** and only within the player’s **allowed bench row** derived from `Board.HostPlayerId/GuestPlayerId`.
  - Successful moves publish the correct structured grid event (`Grid.UnitMoved` / `Grid.UnitSwapped`).

### Constraints / invariants
- **Server authority**: client requests only; server derives phase + allowed bench row; server commits occupancy.
- **Occupancy is canonical**: legality is based on `FBrawlGridCoord` + `ABrawlBoardActor::Occupancy` (not actor transforms).
- **Combat restrictions**:
  - field is locked
  - bench-only movement
  - must remain within the player’s allowed bench row (`Y=0` host, `Y=1` guest)
- **Rewards restrictions**:
  - no player-initiated moves

### Primary references
- `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp`
  - `ABrawlPlayerController::ServerRequestMoveUnit_Implementation`
- `Source/BrawlGrid/Private/Actors/BrawlBoardActor.cpp`
  - `ABrawlBoardActor::ServerMoveUnit` (canonical move legality)
- `Source/BrawlCore/Public/Events/BrawlEvents.h`
  - `FBrawlGridUnitMovedEvent`, `FBrawlGridUnitSwappedEvent`
- `Source/BrawlMatch/Public/Subsystems/BrawlMatchEventLogSubsystem.h`
  - buffered event retrieval for assertions

### Deliverables
- **New automation tests (LVL_Sandbox)**, suggested names:
  - `Brawl.Match.MoveUnit.RejectsRewards.LVL_Sandbox`
    - Arrange: spawn PC/PS + Board; place unit on bench.
    - Act: `PhaseTag = Phase.Rewards`, call `ServerRequestMoveUnit`.
    - Assert:
      - occupancy unchanged
      - no `Grid.*` event emitted
  - `Brawl.Match.MoveUnit.Combat_BenchOnly_AllowedBenchRowEnforced.LVL_Sandbox`
    - Arrange: set Board host+guest ids and set the caller as either host or guest.
    - Act/Assert:
      - a bench->bench move within the allowed bench row succeeds
      - a move to the other bench row fails
      - a move to a field coord fails
      - successful move emits exactly one grid event (`Grid.UnitMoved` or `Grid.UnitSwapped`) with correct base fields (`PhaseTag`, `PlayerId`, `InstigatorUnitId`, etc.)

### Acceptance criteria
- Tests are deterministic and stable.
- `ServerRequestMoveUnit` behavior matches the phase semantics:
  - rejects Rewards
  - combat bench-only + allowed bench row enforced
- Grid move events are emitted only on successful commits.

### Rules Applied
- `rules/brawl-implementation.md` (phase semantics; combat bench-only; rewards lockout)
- `rules/brawl-replication-contract.md` (occupancy canonical; server-authoritative placement)
- `rules/brawl-event-log-schema.md` (structured event emission for placement)

## Workstream 2 — Match: Add missing automation coverage + checklist update for combat **field** ability-equip rejection

### Objective
- `ServerRequestEquipUnitAbilities` is intended to be allowed in `Phase.Combat` **bench-only**.
- Add the missing automated coverage that **field** equip attempts during combat are rejected.
- Update the server validation checklist to match current intended behavior.

### Constraints / invariants
- **Bench-only interaction in combat**: ability loadout changes during combat must be restricted to bench units.
- **Server authority**: clients request only; server validates phase + placement via `TryFindUnitCoord`.
- **Conservative validation**: if placement cannot be resolved, treat as not equip-eligible in `Phase.Combat`.

    - Move the unit to a **field** coord using `Board->DebugClearOccupancy()` + `Board->DebugSetUnitAtCoord(FieldCoord, UnitId)`.
    - Attempt `ServerRequestEquipUnitAbilities(...)`.
    - Assert:
      - `EquippedBasicAbilityId` and `EquippedUltimateAbilityId` unchanged
