## Workstream 3 — Economy/Match: Allow `BuyXP` + `ShopReroll` during `Phase.Combat`

### Objective
- Allow players to **buy XP** and **reroll shop offers** during `Phase.Combat` (and planning-like).
- Keep `Phase.Rewards` locked down.

### Constraints / invariants
- **Server authority**: Clients send requests only; server validates and commits.
- **No hidden randomness**: Rerolls remain seeded server-only RNG (existing `UBrawlShopComponent` behavior).
- **Rate limiting preserved**: Keep the existing request cooldowns (`NextBuyXPAllowedTimeSeconds`, `NextShopRerollAllowedTimeSeconds`).

### Primary references
- `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp`
  - `ServerRequestBuyXP_Implementation`
  - `ServerRequestShopReroll_Implementation`
- `Source/BrawlEconomy/Private/Components/BrawlShopComponent.cpp` (`ServerRerollOffers`, RNG seed policy)
- `Source/BrawlEconomy/Public/Components/BrawlProgressionComponent.h` (`AddXP`, tuning)
- `Source/BrawlEconomy/Public/Components/BrawlEconomyComponent.h` (`TrySpendGold`)

### Deliverables
- **Phase gate update**:
  - Permit `Phase.Combat` in both RPCs.
  - Keep `Phase.Rewards` forbidden.
- **Event logging remains correct**:
  - `Economy.BuyXP` and `Economy.Reroll` events should be emitted with the *current* `PhaseTag` (now potentially `Phase.Combat`).
- **Automation tests (LVL_Sandbox)**:
  - `Brawl.Economy.BuyXP.AllowedInCombat.LVL_Sandbox`
    - Arrange: spawn PC/PS, give gold, set `PhaseTag = Phase.Combat`.
    - Act: call `ServerRequestBuyXP()`.
    - Assert: gold decreases by cost and XP increases by expected amount.
  - `Brawl.Economy.ShopReroll.AllowedInCombat.LVL_Sandbox`
    - Arrange: spawn PC/PS, ensure shop has offers, set `PhaseTag = Phase.Combat`.
    - Act: call `ServerRequestShopReroll()`.
    - Assert: gold decreases by reroll cost and offer ids list changes.

### Acceptance criteria
- `BuyXP` and `ShopReroll` succeed in `Phase.Combat` and remain rejected in `Phase.Rewards`.
- Tests are deterministic and stable.

### Rules Applied
- `rules/brawl-implementation.md` (server authority; phase semantics)
- `rules/brawl-replication-contract.md` (requests validated/committed on server)
- `rules/brawl-server-validation-checklist.md` (server-side validation posture)

## Workstream 4 — Economy/Match: Allow `SellUnit` during `Phase.Combat` (bench-only)

### Objective
- Allow selling units during `Phase.Combat`, but **only if the unit is on the bench**.
- Prevent selling **field** units during combat.

### Constraints / invariants
- **Bench-only interaction in combat**: Selling is treated as an interaction; during combat it must be restricted to bench units.
- **Conservative validation**: If placement can’t be resolved from authoritative occupancy (`TryFindUnitCoord` fails), treat the unit as **not sellable** in `Phase.Combat`.
- **Arena-aware**: If `ActiveBoardActor` is an arena board, selling should operate against that board’s occupancy.
- **Shared pool correctness**: Selling returns the unit’s `UnitDataId` to `UBrawlSharedPoolSubsystem` (existing behavior).

### Primary references
- `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp` (`ServerRequestSellUnit_Implementation`)
- `Source/BrawlGrid/Public/Actors/BrawlBoardActor.h` (`TryFindUnitCoord`, `ServerRemoveUnit`)
- `Source/BrawlMatch/Public/Game/BrawlPlayerState.h` (`GetActiveBoardActor`)
- `Source/BrawlMatch/Public/Game/BrawlGameState.h` (`GetPhaseTag`)

### Deliverables
- **Phase gate update**:
  - Permit `Phase.Combat`.
  - Keep `Phase.Rewards` forbidden.
- **Bench-only enforcement in combat**:
  - When `PhaseTag == Phase.Combat`:
    - Require `Board->TryFindUnitCoord(UnitId, Coord)` to succeed.
    - Require `Coord.bIsBench == true`.
    - (Optional hardening) Require `Coord.Y == AllowedBenchRow` derived from `HostPlayerId/GuestPlayerId`.
- **Automation tests (LVL_Sandbox)**:
  - `Brawl.Economy.SellUnit.AllowedInCombat_BenchOnly.LVL_Sandbox`
    - Arrange: place a player-owned unit on bench, set `PhaseTag = Phase.Combat`.
    - Act: sell it.
    - Assert: unit removed from board occupancy and roster; gold increases; shared pool return is invoked (can be asserted indirectly via pool counts or by ensuring no crash + roster/gold invariants).
  - `Brawl.Economy.SellUnit.RejectsCombatFieldSell.LVL_Sandbox`
    - Arrange: place a player-owned unit on field, set `PhaseTag = Phase.Combat`.
    - Act: attempt to sell.
    - Assert: unit/roster/gold unchanged.

### Acceptance criteria
- Selling in combat works for bench units and is rejected for field units.
- Selling still behaves as before in planning/itemshop.
- Tests pass reliably.

### Rules Applied
- `rules/brawl-implementation.md` (combat interaction rules; server authority)
- `rules/brawl-replication-contract.md` (board occupancy canonical)
- `rules/brawl-server-validation-checklist.md` (reject invalid/malformed client requests)

## Workstream 5 — Items/Match: Allow item equip during `Phase.Combat` (bench-only)

- Allow equipping/unequipping unit items during `Phase.Combat`, but **only onto bench units**.
- Keep `Phase.Rewards` locked down.

### Constraints / invariants

- **Server authority**: Inventory consumption and equip commits happen server-side only.
- **Arena-aware**: Must work while a player is a guest on an arena board (`ActiveBoardActor != BoardActor`).

### Primary references
- `Source/BrawlMatch/Private/Game/BrawlPlayerController.cpp` (`ServerRequestEquipUnitItem_Implementation`)
- `Source/BrawlEconomy/Public/Components/BrawlItemInventoryComponent.h` (inventory ownership/replication)
- `Source/BrawlUnit/Public/Components/BrawlUnitItemComponent.h` (equip logic)
- `Source/BrawlGrid/Public/Actors/BrawlBoardActor.h` (`TryFindUnitCoord`)

### Deliverables
- **Phase gate update**:
  - Permit `Phase.Combat` for item equip/unequip.
  - Keep `Phase.Rewards` forbidden.
- **Bench-only enforcement in combat**:
  - When `PhaseTag == Phase.Combat`:
    - Require `Board->TryFindUnitCoord(UnitId, Coord)` to succeed.
    - Require `Coord.bIsBench == true`.
    - (Optional hardening) Require `Coord.Y == AllowedBenchRow`.
- **Automation tests (LVL_Sandbox)**:
